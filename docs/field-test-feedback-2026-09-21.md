# Замечания полевого теста — 21.09.2026

Статус: зафиксировано после встречи, требует разборки по экранам и приёмки в реальном сценарии.

## Блокирует работу

| Наблюдение | Ожидаемый результат |
| --- | --- |
| Директор не может войти в служебную админку и добавлять данные. | Директор имеет полный доступ к Django-админке и ко всем объектам, сохраняя роль руководителя в рабочем интерфейсе. |
| Специалиста нельзя создать, непонятно назначение поля «пользователь для входа». | В форме есть понятный сценарий: создать учётную запись для мобильного кабинета или оставить специалиста без доступа; оба пути сохраняются с первого раза. |
| Категории услуг не создаются при добавлении услуги. | Категорию можно выбрать или создать без потери данных услуги. |
| Контрагент не сохраняется. | Карточка сохраняется с первого нажатия и показывает точную ошибку обязательного поля, если оно не заполнено. |
| Иногда поле срабатывает только по стрелке или со второго раза; иногда нужно сохранять дважды. | Все селекты, автоподборы и формы работают одним предсказуемым действием, без повторного сохранения. |
| Страница специалиста скрывает занятия за день, нет прокрутки. | Весь список занятий доступен на телефоне и на компьютере, есть прокрутка и понятная высота блока. |
| Панель информации перекрывает форму договора. | На узких экранах панель не закрывает обязательные поля и кнопки. |

## Роли и рабочие сценарии

| Наблюдение | Ожидаемый результат |
| --- | --- |
| Слишком многое приходится добавлять через техническую админку; в ней и в рабочем интерфейсе разные понятия. | Основные ежедневные сущности создаются из рабочего интерфейса. Техническая админка остаётся для настройки и исправления данных. |
| Вручную нужно добавить специалиста в кабинет при форс-мажоре. | Администратор и директор могут внести разовое назначение специалиста в кабинет с причиной и журналом изменения. |
| При создании получателя открытие представителя убирает введённые данные. | Связанный представитель создаётся разворачиваемой секцией в той же форме или в безопасном диалоге без потери введённых данных. |
| На ребёнка добавляется только один счёт. | Проверить правило: один основной счёт на источник финансирования либо несколько счетов при разных источниках; форма должна объяснять ограничение и не блокировать допустимый второй счёт. |
| Сертификат нужен сразу при договоре, если он существует. | В договоре есть явный выбор «сертификат есть / нет», а форма открывает создание сертификата без потери договора. |

## Термины и понятность интерфейса

| Наблюдение | Ожидаемый результат |
| --- | --- |
| «Тип кабинета» непонятен. | Пояснение у поля и понятные варианты: индивидуальный кабинет, зал, группа, специализированное оборудование, другое. |
| «Программа», «первичная консультация», «серия занятий» непонятны. | Экран объясняет цепочку: программа — план помощи; блок — этап программы; серия — повторяющиеся занятия по расписанию. Первичная консультация создаётся отдельным понятным сценарием. |
| Непонятны «риски» в дашборде. | Каждая карточка риска содержит причину, объект, последствия и кнопку действия. |
| Непонятно, почему при непроведённом занятии не списываются средства. | У занятия явно показано правило: списание происходит только после отметки «проведено»; отмена и неявка имеют отдельные правила и основание. |
| Непонятны «архивировано» и поля контрагента в админке. | Архив означает исключение из новых операций без удаления истории; в рабочем интерфейсе есть понятное описание и фильтр. |
| Информационные сообщения плохо заметны. | Изменения, сохранение, создание записи и ошибки показываются заметным уведомлением рядом с действием. |

## Данные и формы

| Наблюдение | Ожидаемый результат |
| --- | --- |
| Для цвета нет заготовок. | Палитра корпоративных и контрастных цветов плюс ручной выбор. |

| Нет даты инвентаризации. | Есть дата последней инвентаризации и история проверок. |

| Местонахождение и кабинет оборудования должны быть необязательными. | Оборудование можно создать без привязки, а затем назначить место. |

## Порядок работы

1. Воспроизвести и исправить блокирующие ошибки сохранения и доступа.
2. Привести создание получателя, представителя, специалиста, услуги, кабинета, контрагента и счёта к единым понятным сценариям.
3. Исправить мобильный экран специалиста и перекрытия форм.
4. Уточнить финансовые правила, оборудование и документы.
5. Провести повторную приёмку по ролям: директор, администратор, специалист.
