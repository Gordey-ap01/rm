# Интервью директора 2026-06-23

Статус: очищенная версия для репозитория. Сырой файл интервью и тестовые
данные с ФИО, телефоном и медицинскими деталями не коммитить.

## Проверка текущей системы

- При создании получателя нужен удобный сценарий добавления представителя без
  возврата в отдельный экран.
- В основной форме представителя должен быть полный набор типов отношений,
  согласованный с админкой: мать, отец, бабушка, дедушка, другое.
- После сохранения представителя интерфейс должен возвращать администратора в
  контекст карточки получателя, а не оставлять в тупиковом состоянии формы.
- Справочники через админку остаются допустимым fallback, но ежедневная работа
  администратора должна происходить в основном интерфейсе.

## Представители

- У одного получателя может быть несколько представителей.
- Один представитель является основным подписантом договора.
- Дополнительные представители могут получать расписание, если включен флажок
  отправки расписания.
- Родители и сопровождающие не учитываются как участники занятия и не должны
  занимать вместимость кабинета.

## Расписание и кабинеты

- Занятия могут быть индивидуальными и групповыми.
- В групповом занятии может быть несколько получателей.
- В одном занятии может работать несколько специалистов.
- Если занятие индивидуальное, специалист считается занятым на это время, и
  система не должна ставить ему другого получателя.
- Для группового занятия система должна разрешать добавление получателей до
  лимита, заданного правилами занятия и кабинета.
- Кабинет должен иметь отдельные настройки:
  - ограничен ли кабинет одним специалистом одновременно;
  - сколько специалистов допускается одновременно, если ограничение выключено;
  - ограничен ли кабинет одним получателем;
  - сколько получателей допускается одновременно, если ограничение выключено;
  - разрешены ли групповые занятия.
- При ручном создании занятия система должна предупреждать администратора о
  нарушении правил кабинета.
- Нужен безопасный механизм удержания/подтверждения:
  - перейти к настройкам кабинета и исправить постоянное правило;
  - либо дать одноразовое разрешение на конкретное занятие с фиксацией причины
    и автора.

## Финансы, гранты и квоты

- Источники финансирования включают личные оплаты, гранты, фонды и спонсоров.
- Грантовая квота задается сначала на услугу или направление, а затем
  распределяется между специалистами.
- Должен поддерживаться быстрый вариант распределения сразу как
  "специалист + количество занятий".
- Грант можно учитывать как количество занятий по каждому специалисту.
- У занятия в рамках гранта может быть стоимость для специалиста.
- Распределение по специалистам может меняться в период реализации проекта.
- Перенос остатка между каскадами и пересчет количества занятий выполняет
  администратор.

## Зарплата и табель

- Зарплата зависит от длительности и наименования услуги.
- Для грантов нужна отдельная настройка начислений: фиксированная сумма или
  сумма за занятие.
- Начисление зарплаты выполняется при статусе занятия "списать".
- Нужно учитывать назначения вторым специалистом.

## Переносы и отмены

- Списание за перенос можно оставить на решении администратора.
- При отмене день-в-день система должна предупреждать и помогать принять
  решение, но окончательное действие остается у администратора.
- Для ситуаций без свободных окон нужна цепочка переносов, где одно занятие
  освобождает окно для другого. Такую цепочку нельзя смешивать с
  альтернативными вариантами переноса одного и того же занятия.

## Импорт

- Импорт Excel нужен после стабилизации модели данных.
- На раннем этапе допустим только preview-режим с проверкой колонок и строк без
  записи в базу.
