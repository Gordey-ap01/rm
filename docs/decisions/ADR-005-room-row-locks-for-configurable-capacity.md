# ADR-005: блокировка строки кабинета для изменяемой вместимости

## Статус

Accepted

## Дата

2026-07-25

## Контекст

Для получателей и специалистов PostgreSQL exclusion constraints защищают
пересекающиеся интервалы. Кабинет может разрешать несколько одновременных
занятий, причем лимиты специалистов и получателей задаются в самой настройке
кабинета. Обычный exclusion constraint выразил бы только запрет любого
пересечения и сломал бы разрешенные групповые сценарии. Уникальный constraint
также не умеет сравнивать число пересекающихся строк с лимитом из другой
таблицы.

Проверка только в форме небезопасна: два администратора могут увидеть одно
свободное место до сохранения любого из занятий.

## Решение

Штатные write-path занятия берут `SELECT ... FOR UPDATE` на строке каждого
затронутого кабинета в стабильном порядке `pk`, затем повторяют проверку
вместимости в той же транзакции. Блокировка сохраняется до записи занятия и
его snapshot-строк.

Existing PostgreSQL exclusion constraints для child/staff остаются второй
линией защиты. Одноразовый override не отменяет блокировку: он только разрешает
осознанное отклонение с audit reason.

## Альтернативы

### Запретить любое пересечение в кабинете

Отклонено: это противоречит требованию групповых занятий и нескольких
специалистов при явной вместимости больше одного.

### Таблица слотов/резерваций кабинета

Отложено: она смогла бы дать DB-level counting constraint, но потребует
дискретизации времени, backfill и нового жизненного цикла reservation. Для
текущей нагрузки это больше риск миграции, чем польза.

### Только optimistic retry после ошибки

Отклонено: без DB constraint ошибка может не возникнуть, а запись уже превысит
лимит.

## Последствия

- Одновременные записи в один кабинет коротко сериализуются.
- Записи в разные кабинеты не блокируют друг друга.
- Добавление нового штатного write-path требует подключения к этому contract.
- Решение проверяется только PostgreSQL concurrency tests; SQLite остается
  функциональным, но не доказательством конкурентной безопасности.
