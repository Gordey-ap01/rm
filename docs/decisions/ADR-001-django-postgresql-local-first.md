# ADR-001: Django + PostgreSQL, локальный first deployment

## Status

Accepted

## Date

2026-05-14

## Context

Проект реабилитационного центра должен срочно заменить ручные Excel-таблицы, бумажные заметки и ручные сверки. Первая версия нужна одновременно администратору и руководителю. Действующего WordPress-сайта, который нужно сохранить, нет. Развертывание требуется локально, потому что система будет обрабатывать персональные данные получателей и родителей, договорные данные, рекомендации, документы и фото/видео материалы.

Пользователь отдельно указал критерий выбора стека: что проще делать и сопровождать с ИИ.

## Decision

Использовать Django + PostgreSQL как основной стек MVP.

PostgreSQL будет единственным источником истины. Django будет отвечать за модели, миграции, права, формы, админку, рабочие экраны администратора/руководителя и доменную логику. WordPress не используется в первой версии. NocoDB может остаться только как прототип или вспомогательный табличный интерфейс, но не как ядро расписания, балансов и грантов.

Deployment path: сначала локальный запуск на ноутбуке, затем перенос на мини-сервер. На старте система должна выдерживать 2-3 одновременных рабочих места. Мобильный экран специалиста входит в MVP. Данные сначала тестовые, импорт Excel выполняется после проверки базовой модели. Упаковка и запуск через Docker. Интерфейс на русском. Авторизация специалистов в MVP через логин/пароль.

## Alternatives Considered

### WordPress + NocoDB

Плюсы:

- быстро сделать простые формы и таблицы;
- подходит для публичного сайта или прототипа.

Минусы:

- сложнее надежно защитить расписание от пересечений;
- сложнее тестировать финансовую логику и ledger;
- критичные права и record-level ограничения в NocoDB завязаны на платные/enterprise-возможности;
- WordPress не нужен, так как текущего сайта нет.

Rejected for core system.

### Next.js / Node / Prisma

Плюсы:

- современный стек;
- удобен для SPA и будущего SaaS.

Минусы:

- больше решений нужно принимать с нуля;
- админку, формы, роли и back-office придется собирать вручную;
- для срочного локального MVP это длиннее.

Deferred.

### Directus + PostgreSQL

Плюсы:

- хороший data studio поверх PostgreSQL;
- REST/GraphQL API, permissions, flows.

Минусы:

- доменная логика расписания и финансов все равно нужна отдельно;
- риск, что сотрудники будут редактировать критичные данные напрямую.

Possible later as auxiliary admin/data layer.

## Consequences

- MVP можно делать вертикальными срезами и быстро показывать пользователю.
- ИИ будет работать в более предсказуемой структуре: models, migrations, forms, views, admin, tests.
- Критичные правила можно закрепить в PostgreSQL constraints и покрыть тестами.
- Локальное развертывание нужно проектировать с резервным копированием, обновлениями и понятной эксплуатацией.
- UI первой версии будет рабочим back-office, не маркетинговой страницей.
- Первый запуск на ноутбуке требует максимально простой инструкции запуска и резервного копирования, иначе эксплуатация быстро станет хрупкой.
- Excel import нельзя делать до проверки модели на тестовых данных, иначе старые ошибки и неоднозначности попадут в новую базу.
