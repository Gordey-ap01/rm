# Контракт: UI справочников расходов и контрагентов

Дата: 2026-07-18

Статус: выполнен 2026-07-18

## Контекст

После закрытия `docs/21-expenses-assets-contracts-contract.md` модели `CenterExpenseCategory` и `Counterparty` уже используются расходами, договорами пожертвования и import preview, но администратор наполняет эти справочники через Django admin. Это неудобно для ежедневной работы и мешает безопасному preview импорта: ошибки "категория не найдена" и "контрагент не найден" должны исправляться в рабочем UI, не через техническую админку.

## Цель

Дать администратору небольшой product UI для справочников:

- категории расходов центра;
- контрагенты, поставщики, фонды и спонсоры.

## Границы

Входит:

- list/create/edit для `CenterExpenseCategory`;
- list/create/edit/archive/restore для `Counterparty`;
- фильтры, summary и next-action подсказки;
- ссылки из расходов/договоров/import preview к справочникам;
- tests и Browser QA desktop/mobile.

Не входит:

- новые модели или миграции;
- approve/pay расходов;
- реальный Excel import write-path с записью в БД;
- создание `CenterExpense`, `DonationContract`, `LedgerEntry`, `BalanceAccount`, `Payment`, payroll или grant фактов;
- изменение `billing.apply_decision()` или статусов занятий.

## Правила

- `CenterExpenseCategory.is_active=False` скрывает категорию из новых расходов, но не ломает старые расходы и отчеты.
- `Counterparty.archive()` скрывает контрагента из новых расходов и договоров, но сохраняет связи и историю.
- Редактирование справочника не должно переписывать финансовые факты или связанные документы.
- Физическое удаление через product UI не добавлять.
- Forms должны переиспользовать существующие модели и validation, без ad hoc SQL.

## Acceptance Criteria

- Администратор видит список категорий, их тип, активность, порядок и количество связанных расходов.
- Администратор может создать и редактировать категорию без миграций и без создания расходов.
- Администратор видит список контрагентов с типом, контактами, архивным статусом и количеством связанных расходов/договоров.
- Администратор может создать, редактировать, архивировать и восстановить контрагента без удаления связанных данных.
- Страницы расходов, договоров и import preview дают понятный путь к справочникам.
- Focused tests доказывают, что UI не создает `LedgerEntry`, `BalanceAccount`, `Payment`, payroll, billing или grant факты.
- Browser QA desktop/mobile проходит без горизонтального overflow и console/page errors.

## Следующие срезы после выполнения

Только отдельными контрактами:

- юридическая Word-template генерация договоров с placeholders и сохранением `Document`;
- approve/pay для расходов центра;
- import write-path с записью в БД;
- расширение контрагентов под реальные юридические реквизиты, если текущих полей недостаточно.
