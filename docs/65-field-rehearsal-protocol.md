и исправление защиты участников проверены; общий CI новой версии успешен

До допуска также остаются репетиция на конкретном компьютере выезда

Это протокол для учебного теста на вымышленных данных, на **одном ПК**. Он не
обещает доступ с телефона, второго компьютера, LAN или интернета. Реальный
пилот с данными центра имеет отдельные эксплуатационные условия в плане 63.
Ориентир очного теста — 21 сентября, 10:00–12:30; решение о его проведении
нужно принять до 18 сентября, 16:00. Даты остаются предложением до
подтверждения сотрудников и владельца.

на этом же ПК вручную запустить Docker Desktop, дождаться готовности и один раз
успешно прогреть Docker-кэш. Новая или очищенная Docker-среда может потребовать
интернет для образов и зависимостей.

## Учебный запуск и доступы

1. Вручную запустите Docker Desktop и дождитесь состояния «готов».
2. В корне комплекта откройте `START_PILOT.bat`.
3. Откройте в браузере `http://127.0.0.1:18000` на этом же ПК.
4. Используйте только учётные записи: `pilot-admin`, `pilot-director`,
   `pilot-specialist1`, `pilot-specialist2`.
5. Учебный пароль участникам выдаёт технический ответственный: он находится в
   `pilot/.pilot-local.env` как `RM_PILOT_PASSWORD`. Полный файл содержит также
   служебные секреты; его не передавать участникам. Пароли в журнал не записывать.

Перед управляемой перезагрузкой Windows владелец ПК сохраняет собственную
работу. Затем именно владелец перезагружает Windows, технический ответственный
повторяет запуск по шагам выше и фиксирует результат. Не удалять Docker images,
containers, volumes, папку комплекта или локальный env-файл.

## Чек репетиции

В графе «факт» писать наблюдаемое действие или текст ошибки. Статус: `пройден`,
`ошибка` либо `не проверен`; пропуск не означает успех.

| Проверка | Ожидалось | Факт | Статус |
| --- | --- | --- | --- |
| ПК, Docker Desktop, финальная папка и кэш | На указанном ПК Docker готов, комплект запускается из окончательной папки | | |
| Windows reboot и повторный вход | После управляемой перезагрузки приложение открывается, вход восстанавливается | | |
| Администратор: вход и расписание | Есть свой доступ и обычная навигация | | |
| Индивидуальное занятие: создать, конфликт, перенос | Допустимая запись сохранена; конфликт объяснён; перенос виден после обновления | | |
| Групповое занятие | До проведения снятие чистого участника сохраняет остальных; после фактов снятие отклоняется с объяснением и сохранением истории | | |
| Администратор и руководитель: решение | Администратор принимает/отмечает без ответа специалиста; решение руководителя нельзя заменить администратору | | |
| Проведение, прогресс и завершение | Участия согласованы с прогрессом; ограничения и основание понятны | | |
| Учебное списание и повтор запроса | Нет двойного списания; попытка запрещённой корректировки не переписывает деньги | | |
| `STOP_PILOT.bat` затем `START_PILOT.bat` | Данные и история сохраняются; другой Docker-проект не затронут | | |

Порядок сценария важен: сначала проверяйте изменения расписания, затем
отмечайте проведение. После отметки «Проведено» изменение расписания
руководителем ожидаемо отклоняется и не является дефектом.

Не записывая секреты, зафиксируйте: место исходного комплекта

## Допуск и журнал

Допуск к очному учебному тесту возможен, когда репетиция на указанном ПК с
reboot и Stop/Start пройдена, основные сценарии технической репетиции не имеют блокирующей
ошибки, а ответственный, участники, время и офлайн-протокол подтверждены.
Непроверенный телефонный сценарий не закрывается автоматически и не расширяет
объем теста.
Если этот ПК готов, репетиция займёт ориентировочно 1–2 часа; это оценка, а не
обещание. Для другого ПК срок начинается после его подготовки. Это не оценка
2–4 дней новой разработки: такая работа нужна только при обнаружении дефекта.
