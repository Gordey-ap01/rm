# Локальный учебный комплект

Эта папка запускается только внутри папки учебного комплекта, которую создал
`scripts/build_pilot.py`. Она не предназначена для запуска из рабочего
репозитория: перед запуском нужен соседний `pilot-manifest.json`.

## Запуск

1. Вручную запустите Docker Desktop и дождитесь, когда он сообщит о готовности.
   Скрипты не запускают Docker Desktop сами.
2. В корне учебного комплекта откройте `START_PILOT.bat`. Это основной способ
   запуска для Windows. Он вызывает `pilot\Start-Pilot.ps1`.
3. Для автоматической проверки без открытия браузера выполните в PowerShell из
   корня комплекта:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\pilot\Start-Pilot.ps1 -NoBrowser
   ```

4. Откройте `http://127.0.0.1:18000`.

Все четыре учетные записи используют значение `RM_PILOT_PASSWORD` из локального
файла `pilot\.pilot-local.env`:

- `admin`
- `director`
- `specialist1`
- `specialist2`

Файл содержит и пароль БД, но он не нужен для работы с приложением и не должен
передаваться участникам учебного теста.

Скрипт проверяет manifest, создает локальный файл паролей только при первом
запуске, собирает образ, поднимает отдельную PostgreSQL БД, применяет миграции,
собирает статику и выполняет `seed_pilot` для даты из manifest. Повторный запуск
использует те же пароли и базу. Наполнение уже инициализированной учебной базы
ничего не изменяет.

Учебная дата фиксируется в manifest при сборке комплекта. Для первого запуска
выбирайте сегодняшний день или будущую дату; после сборки не редактируйте дату
в manifest. Не переносите уже инициализированный комплект в другую папку:
путь входит в проверку владения Docker-проектом. Для другого компьютера сначала
соберите новый комплект и запустите его в выбранной окончательной папке.

Контейнеры работают в Docker Desktop в фоне, поэтому после закрытия PowerShell
или Codex приложение продолжает работать. Веб-интерфейс опубликован только на
`127.0.0.1:18000`; PostgreSQL не имеет опубликованного порта. Новые письма
согласования сохраняются в очереди БД; наружу учебный комплект их не отправляет.
Обработчик очереди автоматически не запускается, поэтому «Ожидает отправки»
не означает отправленное письмо или полученное согласие. Для технической
проверки можно отдельно выполнить в web-контейнере
`python manage.py process_confirmation_emails --once`; учебный почтовый backend
сохранит письма только в памяти этого процесса. Для чтения количества заданий
без обработки используется `python manage.py process_confirmation_emails --status`.
Реальная почта на рабочем хостинге требует отдельной настройки SMTP и постоянного
обработчика; это не действие сценария учебного запуска.

## Первый запуск и кэш Docker

Первый запуск может загрузить `postgres:17`, базовый образ Python и Python
зависимости. Выполните его при наличии интернета до выезда и дождитесь успешного
сообщения о готовности. После успешной сборки Docker Desktop использует кэшированные
образы, но комплект не обещает, что новая или очищенная Docker-среда сможет
собраться без интернета.

Перед выездом полезно проверить кэш обычным повторным запуском с отключенной
сетью только после того, как первый запуск уже завершился. Не удаляйте Docker
images или volumes между этими проверками.

## Остановка и повторный запуск

Основной способ остановки для Windows — `STOP_PILOT.bat` в корне учебного
комплекта. Эквивалентная команда PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File .\pilot\Stop-Pilot.ps1
```

Скрипт останавливает только проект из проверенного `pilot-manifest.json`; он не
запускает Docker Desktop, не трогает остальные контейнеры и не вызывает
`docker compose down -v`. Данные PostgreSQL, медиа, приватные учебные артефакты
и статика остаются в отдельных Docker volumes этого учебного проекта.

Затем запустите `Start-Pilot.ps1` снова. Учебные записи сохранятся.

Если контейнеры были вручную удалены, но учебные Docker volumes остались,
скрипт намеренно остановится вместо создания нового экземпляра с тем же именем.
Не удаляйте volumes и не запускайте комплект из другой папки: вернитесь к
исходной папке комплекта и обратитесь к техническому ответственному для
восстановления.

## Локальные файлы

- `pilot\.pilot-local.env` — созданные один раз пароль БД, учебный пароль и
  ключ Django. Не отправляйте и не добавляйте этот файл в Git.
- `pilot\.pilot-start.lock` — технический файл блокировки. Скрипт держит
  эксклюзивный дескриптор только на время подготовки; после аварии Windows
  освобождает дескриптор, поэтому этот файл не нужно удалять.

Если Docker Desktop не запущен, запуск завершится с ошибкой до изменения базы.
Исправьте Docker Desktop и повторите команду: штатные сценарии не удаляют ни
папку комплекта, ни Docker volumes.
